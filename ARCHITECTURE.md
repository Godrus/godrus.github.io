# Архитектура и модульность

Сайт построен по принципам DRY, единого источника правды и чёткого разделения слоёв.

## Направление зависимостей

- **app** → **pages** → **shared** (импорт только вниз).
- **shared** не импортирует из pages или app.
- Конфигурация и данные меню — в **shared/config**; UI и layout — в **shared/ui**.

## Слои

- **app:** точка входа, корень приложения (`App.tsx`), подключает роутинг (Pages).
- **pages:** страницы (например `HomePage`); используют только компоненты из shared и данные из config.
- **shared/config:** константы сайта и пункты меню (`site.ts` — `SITE`, `MENU_ITEMS`). Единственный источник правды для навигации.
- **shared/ui:** переиспользуемые компоненты без бизнес-логики.
  - **Layout:** MainLayout, Navbar, PageContainer — общая оболочка и контейнер страницы.
  - **Card:** презентационная карточка (неоморфизм).
  - **ServiceCardLink:** обёртка «ссылка (Link или a) + Card»; по конфигу решает внутренняя/внешняя ссылка.
- **shared/ui/styles:** глобальные переменные темы и неоморфизм (`style.css`, `neumorphism.css`).

## Модульность и универсальность

- Layout не знает о конкретных пунктах меню — получает только `navbarBrand` и `children`.
- Страница не дублирует список сервисов — импортирует `MENU_ITEMS` из config.
- Добавление нового пункта меню — только правка `shared/config/site.ts`.
- Стили: глобальные переменные в одном месте; компонентные стили — CSS Modules (Layout, Card, ServiceCardLink, HomePage).

## Запрещено

- Дублировать пункты меню или константы сайта в нескольких файлах.
- Вшивать разметку/стили, специфичные для одной страницы, в общие Layout/Card без необходимости.
- Импортировать из pages или app в shared.
